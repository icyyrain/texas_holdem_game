# 多人德州扑克设计文档

日期：2026-11-15

## 目标

用 Python 做一个多人在线的无限注德州扑克（No-Limit Texas Hold'em）游戏。玩家用桌面客户端连到同一个服务器，在一张牌桌上对局。

服务器有两种部署方式，用的是同一份代码：

- **本地主机模式**：某个玩家在客户端里点「创建房间」，服务器在他电脑上启动，其他玩家通过局域网 IP（或 Tailscale / ZeroTier 等虚拟局域网）连接。
- **VPS 模式**：在 VPS 上以无界面方式运行服务器，玩家通过公网地址连接。

只用游戏筹码，不涉及任何真实货币。

## 范围

第一版包含：

- 无限注德州扑克，每桌 2–9 人。
- 现金局玩法：固定大小盲、带入筹码、可随时入座和离座。
- 完整的下注流程：翻牌前、翻牌、转牌、河牌、摊牌。
- 玩家动作：弃牌、过牌、跟注、下注、加注、全下。
- 正确的最小加注规则、不足额全下不重新开放加注、边池计算、未被跟注的下注退回。
- 单挑（heads-up）的特殊盲注和行动顺序。
- 服务器权威：洗牌、发牌、动作合法性、结算都只在服务器上进行。
- 每个客户端只收到自己的底牌；其他人的底牌只在摊牌时公开。
- 行动计时，超时自动过牌或弃牌。
- 断线后凭重连令牌回到原座位；断线期间按超时处理。
- 房间可选密码。
- tkinter 桌面客户端，沿用 blackjack 项目的 Canvas 牌桌风格和中英文切换。
- Windows exe 打包（客户端内置服务器，可直接创建房间）。
- 服务器可在 Linux VPS 上用命令行启动。

第一版不包含：

- 真实货币、充值、提现。
- 用户账号、数据库、战绩持久化。
- 锦标赛（盲注升级、淘汰）。
- 其他玩法（奥马哈、限注德州等）。
- 电脑 AI 玩家（之后可作为测试和陪练加入）。
- 观战、聊天、表情。
- 网页端或手机端客户端。

## 架构

```
texas_holdem_game/
  src/holdem/
    core/        # 纯游戏逻辑，不依赖网络和界面
      cards.py       # Card、Deck
      evaluator.py   # 7 选 5 牌型评估与比较
      betting.py     # 下注轮状态、合法动作、最小加注
      pots.py        # 主池、边池计算与分配
      table.py       # 座位、按钮位、盲注、一手牌的完整流程
    protocol.py  # 消息类型定义、JSON 编解码、协议版本
    server/      # asyncio + websockets，房间与连接管理
    client/      # tkinter 界面 + 网络线程
    i18n.py      # 界面文字，zh / en
  tests/
  assets/
  scripts/
```

原则：

- `core` 是唯一的规则来源，没有任何 I/O，可以完全用单元测试覆盖。
- 服务器把 `core` 包一层：接收消息、校验、调用 `core`，再把结果按玩家视角广播出去。
- 客户端不做规则判断，只显示服务器给的状态，并发送玩家的意图。服务器下发的「可选动作」决定按钮能不能点。

## 核心模型

`Card` / `Deck`：从 blackjack 项目的 `cards.py` 改造而来。洗牌用 `secrets.SystemRandom`。测试时可以注入固定顺序的牌堆。

`HandRank`：牌型评估结果，是可以直接比较大小的元组，例如 `(牌型等级, 关键牌...)`。需要正确处理 A-2-3-4-5 顺子、同花顺、踢脚比较和平分。

`Seat`：座位号、玩家 ID、筹码、本手牌已投入金额、状态（空座、入座、本手中、已弃牌、全下、暂离）。

`Pot`：金额和有资格争夺它的座位集合。

`HandState`（一手牌）：

- 按钮位、小盲位、大盲位
- 牌堆、公共牌、每个座位的底牌
- 当前街（preflop / flop / turn / river / showdown）
- 当前行动座位
- 当前最高下注额、最小加注额、最后一个完整加注的座位
- 已行动座位（用于判断这一轮下注是否结束）
- 底池列表
- 事件日志

`Table`：一张桌的配置（盲注、最大人数、带入范围、行动时限）和座位列表，负责开始新一手牌、移动按钮位。

主要方法：

- `Table.sit(player_id, seat, buy_in)` / `Table.leave(player_id)`
- `Table.start_hand()`
- `HandState.legal_actions(seat)`：返回可选动作，以及下注或加注的最小值和最大值
- `HandState.apply(seat, action, amount)`
- `HandState.is_complete()` / `HandState.results()`

## 规则细节

1. **盲注**：小盲在按钮左边，大盲在小盲左边。单挑时按钮位下小盲，翻牌前先行动，翻牌后后行动。
2. **行动顺序**：翻牌前从大盲左边开始；翻牌后从按钮左边第一个还在牌局中的玩家开始。
3. **最小加注**：加注后的总额至少要比当前最高下注多出「上一次完整加注的增量」，翻牌前这个增量最少是一个大盲。
4. **不足额全下**：全下金额不够一个完整加注时，不会给已经行动过的玩家重新加注的权利，他们只能跟注或弃牌。
5. **下注轮结束**：所有没弃牌、没全下的玩家都已行动，而且投入额一致。
6. **提前结束**：只剩一人没弃牌时，他直接赢下所有底池，不需要亮牌。
7. **全员全下**：没人能继续行动时，直接把剩余公共牌发完再摊牌。
8. **边池**：按每个玩家本手的总投入分层，每层底池只由投入达到该层的玩家争夺。
9. **未被跟注的下注**：多出来、没人跟的部分退回给下注者。
10. **平分**：底池平分；分不开的零头给按钮左边最近的赢家。
11. **摊牌**：第一版简化为所有还在牌局中的玩家都自动亮牌。

## 网络与协议

- 传输：WebSocket，一条消息一个 JSON 对象，都带 `type` 字段，连接建立时交换协议版本。
- 默认端口 `8765`，可以配置。

客户端发给服务器：

| type | 内容 |
|---|---|
| `hello` | 协议版本、昵称、房间密码、重连令牌（可选） |
| `sit` | 座位号、带入金额 |
| `leave` | 离座 |
| `action` | `fold` / `check` / `call` / `bet` / `raise` / `all_in`，以及金额 |
| `rebuy` | 补充筹码（只在不在牌局中时） |

服务器发给客户端：

| type | 内容 |
|---|---|
| `welcome` | 玩家 ID、重连令牌、桌子配置 |
| `table_state` | 当前完整状态的**个人视角**快照：只包含自己的底牌 |
| `event` | 增量事件：发牌、某人行动、进入下一街、摊牌、分配底池；客户端靠它播放动画 |
| `your_turn` | 可选动作、下注范围、截止时间 |
| `error` | 错误码和说明（例如动作不合法、密码错误） |

断线重连时，服务器先发一次完整的 `table_state`，再继续发增量事件。客户端以 `table_state` 为准重新同步显示状态。

## 服务器

- 基于 `asyncio` 和 `websockets`。
- 第一版一个服务器进程只开一张桌，房间管理留好接口，之后可以扩展成多张桌。
- 所有客户端输入都要校验：消息格式、是否轮到他、动作和金额是否合法。不合法就回 `error`，状态不变。
- 行动计时器由服务器维护。超时后能过牌就过牌，否则弃牌，并把这个玩家标记为暂离。
- 启动方式：

```powershell
python -m holdem.server --host 0.0.0.0 --port 8765 --password xxx
```

- VPS 部署：提供 systemd 服务示例。需要加密时，用 Caddy 或 nginx 做反向代理，提供 `wss://`。

## 客户端

- tkinter，整张牌桌画在一个 Canvas 上，椭圆牌桌，最多 9 个座位围着摆放。
- 启动后有两个入口：
  - **创建房间**：在后台线程里启动内置服务器，监听 `0.0.0.0`，并显示本机局域网 IP 给其他人连接。
  - **加入房间**：输入地址、端口、昵称和密码。
- 网络在单独的线程里跑一个 asyncio 事件循环。收到的消息放进 `queue.Queue`，界面线程用 `root.after` 轮询取出处理。tkinter 只在主线程里操作。
- 沿用 blackjack 的做法：动画播放期间锁住操作按钮，显示状态落后于服务器状态，动画队列播完后再和最新的 `table_state` 对齐。
- 下注控件：弃牌、过牌/跟注、下注/加注按钮，加注金额滑条，以及「1/2 池」「3/4 池」「满池」「全下」快捷按钮。
- 中英文切换。

## 测试策略

`core` 按测试驱动开发，测试量最大：

- 牌型评估：每种牌型的识别、A 作为最小牌的顺子、同牌型比较踢脚、平分。
- 盲注和行动顺序，包括单挑。
- 最小加注和加注后的再加注。
- 不足额全下不重新开放加注。
- 下注轮结束的判断。
- 只剩一人时提前结束。
- 多人不同金额全下时的边池分层和分配。
- 未被跟注的下注退回。
- 零头分配。
- 筹码守恒：每手牌结束后所有人筹码加起来不变。

协议：每种消息都要测编解码往返；格式错误的输入要被拒绝。

服务器：用 pytest-asyncio 在本机起一个服务器，接几个模拟客户端，跑完整的几手牌。重点验证：每个客户端看不到别人的底牌、不合法动作被拒绝、超时处理、断线重连。

客户端：和 blackjack 一样，替换调度函数，确定性地推进动画；用假的网络层喂消息，验证显示和按钮状态。

## 里程碑

1. 项目脚手架、conda 环境、从 blackjack 拷入素材。
2. `core`：牌、牌型评估。
3. `core`：下注轮、边池、完整一手牌流程。
4. 命令行模拟器：在一个进程里模拟多个玩家对局，用来手动检查规则。
5. 协议和服务器，加一个极简的文字客户端，在本机开多个窗口联机。
6. tkinter 牌桌客户端：创建房间和加入房间。
7. 断线重连、行动计时、房间密码。
8. VPS 部署文档、exe 打包。

## 风险与决策

- **规则正确性是最大风险**，尤其是边池和最小加注。所以 `core` 先做，而且不依赖网络就能完整测试。
- **防作弊靠服务器权威**。客户端永远拿不到别人的底牌和牌堆顺序。第一版不做更多防作弊措施。
- **安全**：VPS 上的服务器暴露在公网。所有输入都必须校验，限制消息大小，设置房间密码，需要时用 `wss://`。第一版没有账号系统，昵称不做唯一性认证。
- **tkinter 和 asyncio 的线程边界**：网络线程绝不直接操作界面，只通过队列传消息。
- **本地主机模式的连通性**：跨网络连接需要端口转发或虚拟局域网，客户端只负责显示本机 IP 并给出提示，不做内网穿透。
- **素材授权**：复用卡牌素材前先确认来源和许可证。
