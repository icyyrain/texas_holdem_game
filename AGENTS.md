# Agent Notes

Design spec: `docs/specs/2026-11-15-texas-holdem-design.md`.

## Commands

- Tests: `conda run -n holdem-game pytest`
- Server: `conda run -n holdem-game python -m holdem.server --port 8765`; desktop client: `conda run -n holdem-game python -m holdem.client` (talks to `ws://127.0.0.1:8765` unless `HOLDEM_SERVER` names another server); text client: `python -m holdem.textclient --name alice` (seats are 1-based in the text client, 0-based in the protocol).
- Rules simulator: `conda run -n holdem-game python -m holdem.sim --players 3` (hot-seat, all cards shown; `--bots 1,2,3 --hands 20 --seed 7` runs unattended). `conda run` pipes output through the console code page, so card suits can show as mojibake; run the env's `python.exe` directly to see them.
- Windows exe: `powershell -ExecutionPolicy Bypass -File .\scripts\build_exe.ps1 [-Server wss://host:port]` writes a one-file `dist\Holdem.exe` with `assets/cards`, `assets/cards_small` and `assets/server_url.txt` bundled (`card_images.resource_root` reads them from `sys._MEIPASS`). `-Server` writes `assets/server_url.txt`, which is git-ignored so the real server address never reaches the public repo; later builds reuse it. The committed PNGs are used as they are; the script renders them only if a folder is incomplete, because re-rendering produces tiny antialiasing differences that show up as changed files.
- VPS deployment: `docs/deploy.md` with `deploy/holdem.service` (systemd), `deploy/holdem.env.example`, `deploy/Caddyfile` and `deploy/nginx.conf`. The server reads `HOLDEM_PASSWORD` when `--password` is not given and does not import tkinter. Section 4c covers a VPS whose port 443 is taken: Caddy on another port, reusing an existing certificate through systemd `LoadCredential`, with a path unit that restarts Caddy on renewal.
- `scripts/prepare_card_images.py` needs cairo DLLs from the conda env, so run it through `conda run` (activation puts `Library\bin` on PATH).

## Architecture

- `holdem.core` is the only source of game rules and does no I/O. Chips are integers.
- `core/table.py`: `Table` owns seats and the button; `HandState` runs one hand. Seat numbers increase clockwise. A running hand moves chips in and out of the shared `Seat.stack` objects, so table stacks are always current.
- BET/RAISE amounts are the player's street total ("raise to"), not the increment. Illegal moves raise `IllegalActionError` (a `ValueError`) and leave the state unchanged.
- Re-raise rights: a player who already acted may raise again only if the bet grew by at least the last full raise since then (`HandState._can_raise`), which covers both short all-ins and short all-ins that add up to a full raise.
- `HandState.events` is the hand log (`blind`, `hole_cards`, `action`, `burn`, `street`, `uncalled_returned`, `showdown`, `award`, ...), with cards as codes. `hole_cards` events are private to their seat; the server must filter them. `burn` carries no card; burned cards stay in `HandState.burned` and are never sent to clients.
- Simplifications for v1: the button moves to the next player with chips (no dead button), and a short all-in big blind still sets the full big blind as the price to call.
- Cards use two-character codes (`"AS"`, `"TH"`); `Card.code` is also the PNG name in `assets/cards`. `Card.value` runs 2–14 (ace high).
- `protocol.py` defines every message. `decode_client` validates strictly (exact fields, no bools as ints, size limit); server messages are built with its helper functions.
- Protocol flow (v3): `hello` → `welcome` + `rooms` (the lobby); `create_room` / `join_room` → `room_joined` + `table_state` (a table); `leave_room` → `room_left` + `rooms`. Only sessions in the lobby get `rooms`, so a client that receives one at the table knows its room closed.
- `server/lobby.py` `Lobby` is the network-free server: a `Session` per connection (nickname, lobby token, current room and its `Member`), up to `max_rooms` `Room`s keyed by a 6-character id. It checks room passwords through `Room.join`, passes table messages to the session's room, pushes the room list to the lobby whenever it changes (`Room.on_change`), and closes a room (`Room.close`, which also stops its bots and timers) after `empty_room_timeout` seconds with no person connected. `Room` keeps its own members, tokens and seats; the lobby keeps each session's room token and rejoins the room with it on reconnect. Bot names `Bot N` are reserved.
- `server/room.py` `Room` is one table. Anything that plays a seat is a `Participant` with one method, `deliver(message)`: `server/app.py` `Connection` wraps a WebSocket, `bots.py` `BotPlayer` plays in-process. Participants answer through `room.handle(player_id, message)` and must never call back into the room from inside `deliver`; bots schedule their move with `room.schedule`.
- Bot policies take a `strategy.Situation` (public table facts plus the bot's own hole cards, built by `strategy.situation_for(hand, seat)`) and a `random.Random`, and return `(action, amount)`. `bots.random_action` and `strategy.smart_action` are registered in `bots.POLICIES`; servers and the simulator default to `smart`, `Room.add_bot` and `BotPlayer` to `random` (keeps room tests fast). `smart_action` runs Monte Carlo equity on the server's event loop, capped by `strategy.MAX_EVALUATIONS` (about 75 µs per seven-card evaluation, so about 100 ms per decision); tests shrink `MAX_EVALUATIONS` and `MIN_TRIALS` with monkeypatch.
- `Room` sends each participant its own view: `table_state` shows only their hole cards (plus cards shown at showdown) and other players' `hole_cards` events arrive without cards. Seats whose player left, is away, or whose member is gone are auto-played (check, else fold).
- Reconnecting: a disconnected session waits `reconnect_grace` seconds; `hello` with its `welcome` token rebinds it and the lobby rejoins its room, where a seated player's `Member` (kept with `participant=None`) gets its seat back with a fresh `table_state`, plus `your_turn` if its turn is still running. A rejoin replaces a connection that is still open: `GameServer` sends it `error` `replaced` and hangs up, and `disconnect(player_id, participant)` (lobby and room) ignores the stale connection. Someone without a seat leaves the room at once.
- Action timer: every turn gets `config.action_timeout` seconds, also while the player is offline. On timeout the seat is marked away and then auto-played. Offline players are also marked away when a hand ends (or at once if they hold no live cards), so `Table.start_hand` never deals them in; seats the room marked away for being offline come back automatically on rejoin, other away seats need a client `away` message with `away: false`. `your_turn.time_left` and `table_state.hand.time_left` are seconds left, not timestamps, because client and server clocks differ.
- Room and lobby tests drive time with `tests/helpers.py` `FakeClock` (`schedule`, `time`, `run()` for what is due now, `advance(seconds)`, `step()`); bots there need `think > 0` or they play forever at one instant. Server tests start a real server on port 0.
- `Deck.shuffle()` uses `secrets.SystemRandom` by default; tests build rigged decks with `Deck([...])` (cards are dealt from the end of the list). Hole cards go one per round starting at the small blind; then one card is burned before the flop, the turn and the river. `tests/test_hand.py::rigged_deck` builds such decks.
- UI strings live in `i18n.py` (`zh` and `en` must define identical keys and placeholders; `test_i18n.py` enforces this).
- `client/canvas_ui.py` (colors, rounded rects, chips, `CanvasButton`) is copied unchanged from blackjack_game.
- Card faces load from PNG via `PhotoImage(data=...)`; loading with `file=` failed intermittently under pytest output capture (seen in blackjack_game). `assets/cards` is 96x134 (board), `assets/cards_small` 60x84 (seats); both are rendered from the SVGs by `scripts/prepare_card_images.py`.
- tkinter is touched only on the main thread; `client/network.py` runs its own asyncio loop in a daemon thread and passes messages through a `queue.Queue` polled with `after`. It adds two local message types, `_connect_failed` and `_disconnected`.
- `client/settings.py` `server_url()`: `HOLDEM_SERVER`, else the first line of `assets/server_url.txt`, else `ws://127.0.0.1:8765`. There is no LAN hosting in the client any more.
- `client/app.py` `HoldemApp` has three screens: `login` (nickname), `rooms` (room list and the create-room form) and `table`. Server events become animation steps (`_steps_for`). While they play, `self.view` (what is drawn) lags `self.state` (the last `table_state`) and the action buttons stay locked; when the queue drains, the view is replaced by a copy of the state. Steps start on a later tick so a `table_state` polled in the same batch is used at the end.
- A dropped connection in the lobby or at a table makes the client reconnect every `RECONNECT_MS` with its token (up to `RECONNECT_ATTEMPTS`, then back to the sign-in screen); `error` `replaced` or a refused rejoin also signs out. The action timer bar redraws from `self.deadline` (on `self.clock`) on its own `after` loop.
- `client/layout.py` holds the tkinter-free geometry and pot-preset math. The raise slider picks an index into `layout.bet_steps`: `SLIDER_STOPS + 1` positions spaced exponentially from the minimum to the all-in amount and rounded to the big blind, so neighbouring positions near the bottom often share an amount; the arrow keys (`HoldemApp.step_raise`, `layout.next_step`) skip to the next different amount. Ticks above the slider mark 1/4, 1/2, 3/4 and full pot (`BET_MARKS`, most useful first; a mark whose label would touch one already drawn is left out), and clicking one acts like its preset button. Your seat is always drawn at the bottom; seat numbers run clockwise, so the next seat is on screen left.
- Edit files with Python or the Edit tool, not PowerShell `Get-Content`/`Set-Content`: Windows PowerShell 5.1 reads UTF-8 without a BOM as the ANSI code page and garbles the Chinese strings in `i18n.py` and the GUI tests.
- GUI tests (`tests/test_gui.py`) pass a fake network, a fixed server address and fake `ask_integer` / `ask_password` into `HoldemApp`, replace `app._schedule` with a fake scheduler, and feed server messages through `app.handle_message`.
